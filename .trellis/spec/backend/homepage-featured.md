# Homepage Featured Management

Use when changing the persisted selection or homepage editor permissions.

- A timestamped migration creates `homepage_editors` (unique user relation) and the `homepage_featured` singleton (`key=homepage`, ordered JSON items, revision). All native collection rules are nil; only PB superusers provision editor grants. Never use per-user settings or self-writable user roles for this global configuration. No automatic first-user grant.
- Go handlers in `routes/homepage_featured.go`, registered in `main.go`, own permission summaries, admin GET/PUT and public selection GET. An editor is an authenticated users record with a current grant, or a PB superuser for controlled native operations. Check again inside the transaction when writing; revoked permissions cannot rely on a prior UI capability.
- Save the full list atomically with an expected revision; conflict409 preserves the current list. Validate unique15-character alphanumeric IDs, at most12 entries, optional en/zh reason strings of at most240 Unicode code points, and every route's current eligibility. Empty [] is valid. Body parsing rejects unknown fields and multiple JSON documents, and is size-bounded.
- Public eligibility requires public=true, a nonempty name, a valid anonymously accessible expanded author, and `app.CanAccessRecord(trail, &core.RequestInfo{Auth:nil, Query:map[string]string{}}, trail.Collection().ViewRule)`. Never inherit e.Auth/share parameters, treat FindRecordById as proof of access, or reuse the logged-in-specific TrailViewableByUser helper. Public GET filters whole entries including their recommendation reasons on every read.
- Missing/unpublished/denied entries are omitted; DB/rule/config corruption returns503. Keep machine-readable homepage_* messages stable and do not send DB diagnostics to clients. Public responses no-store; admin responses private/no-store.
- Real permission tests in `db/tests/permissions/homepage_featured_test.go` must use a temporary DB with real migrations and real tokens. Cover anonymous/ordinary/editor/revoked/native bypass, public-rule/share isolation, malformed payloads, Unicode, atomic ordering/clearing, concurrent revision conflict, and actual DB failures. Never test by migrating a human-owned database.
